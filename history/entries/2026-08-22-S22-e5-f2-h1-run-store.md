## Deviations

- **ST-1's mechanical biome reformat.** `history/index.ts`'s three export blocks were reordered alphabetically by import path after `npx biome check --write` — same fix `[E4.F2.H3]`'s ST-2 needed for the identical reason (`organizeImports`). No logic change.
- **ST-3 created `run-store-fs.test.ts` earlier than `plan.md`'s file list implied**, as the driver that actually executes the parameterized `RunStore.contract.ts` `describe` block — without a driver, nothing runs it, and ST-3's own validation bar could not be checked. Flagged explicitly in `execution-log.md` rather than left implicit. ST-4 then extended this same file (per plan) rather than creating a second one, so no filename collision or duplication resulted.
- **A design refinement caught during ST-3 implementation, not anticipated by `design.md`:** the collision pre-check's own `stat` call could fail for a reason other than "not found" (e.g. `EACCES`); wrapped that path in `RunPersistenceError` too, consistent with AC-20's "every raw fs failure is translated" scope.
- **Spec went through a directed re-analysis (revision 2) before any code was written**, at explicit user request ("reanaliza el problema y vuelve a completar la spec"). Found and fixed five gaps in the first draft, one of them a self-contradictory acceptance criterion (a decoy-token test that demanded a field's absence from `metadata.json` while that field's own contract was to be written there). Recorded in `spec.md`'s own Revision Notes section. Because this happened before implementation, the story reached a clean final-QA `pass` on the first attempt — unlike `[E4.F2.H3]`, whose equivalent gap-closing happened post-implementation via an Amendment.
- **One review-agent orchestration mechanic worth recording:** during the 4R review, R3 (Reliability) and R4 (Resilience) ran as background agents; R1 (Risk) and R2 (Readability) returned synchronously in the same tool-call batch. All four were still launched in one parallel batch per protocol; the wait for the two background results was handled via `ScheduleWakeup`, not polling.
