## Deviations

- **Four authorised scope widenings**, each beyond the backlog entry's literal text: **D1** (`persistRun`), **D5** (`resolveReviewRequest`), **D7** (normaliser, changing `[E5.F2.H2]`'s merged behaviour) and **D11** (git adapter fix, changing `[E2.F1.H2]`'s merged code). All user-authorised at checkpoints; all must be declared in the PR description. Final QA confirmed no undeclared fifth widening and no relaxed guard config.
- **`risk-e6h1-014` (high), found by S10's smoke, not by tests.** `git worktree add --detach <path> <branch>` fails for a branch existing only as `remotes/origin/<name>` — the normal case for a PR branch. **661 tests missed it** because `GitPort.contract.ts` defined its fixture branch as one existing *both* locally and as `origin/<name>`, the only shape where `--detach` works. Gap now closed at the port-contract level.
- **S10b's fix was scoped too narrowly, and that was the orchestrator's error, not the worker's.** The handoff said "fix `worktreeAdd`", treating the symptom's location as the boundary. The re-run smoke then died one stage later in `mergeBase` with the identical root cause. S10c completed it across all five ref-taking call sites after a whole-file audit.
- **The first smoke run passed and proved almost nothing.** The throwaway repo's HEAD sat on `feature`, so `baseRef == targetRef`, the diff was empty and the engine approved nothing. Recorded because it is the more instructive result: a green smoke over a degenerate fixture is worse than no smoke.
- **F-7, caught by the final QA review, was a gap in the orchestrator's own bookkeeping**: S10 was run inline, its results recorded as risk resolutions in `state.yaml`, but no `execution-log.md` entry was ever written — three risks cited evidence the log did not contain. Written retroactively in the closing commit.
- `npm run dev` was broken by S9 and unnoticed until then (D10) — the `[E0.F1.H3]` stub never imported source code, so no earlier story could have surfaced it.
