## Delegation Heuristics

- Keep the orchestrator thin.
- Inline only local routing decisions that require at most 3 repo files.
- Delegate when routing, planning, or execution needs 4 or more repo files.
- Delegate read-plus-write work together when implementation is likely.
- Delegate `sddl-proposal`, `sddl-spec`, `sddl-design`, `sddl-plan`, `sddl-executor`, `sddl-qa-review`, `sddl-delivery`, and `sddl-archive` as fresh workers by default, launched via the mapped execution profile.
- Do not run builds, installs, or broad tests inline in the orchestrator.
- Prefer artifact paths and short digests over copied artifact bodies.

## Project Standards (auto-resolved)

Copy only the relevant bullets from this section into delegated prompts.

### repo_conventions

- Persisted artifacts stay in English even when chat is Spanish.
- Runtime files stay under `./sdd-lite/`.
- `state.yaml` is the resume anchor; stage artifacts keep semantic detail.
- Do not invent runtime paths outside `./sdd-lite/`.

### execution

- `sddl-executor` runs one approved stage per invocation.
- Stop on contradiction, scope drift, or blast-radius expansion.
- Do not perform hidden git side effects.
- Record changed files, checks run, blockers, and next action in `execution-log.md`.

### testing

- Prefer the smallest meaningful validation set for the approved stage.
- Final review should start from configured quality commands, then narrow or expand as evidence requires.
- If a useful automated check cannot run, say so explicitly and record the gap.

### review

- Findings should be concrete and evidence-backed.
- `stage` review never closes the change.
- Only `final` review with a clean `pass` may mark the change completed.
- 4R triage: trivial diffs get no lens, standard diffs exactly one, hot-path or >400 changed lines get all four plus one refuter pass.
- Severity floor: only BLOCKER/CRITICAL findings enter the fix loop; WARNING/SUGGESTION are recorded once as `info` and never block.
- Precision gate: report only real, user-impacting defects with concrete evidence; when in doubt, stay silent.
- Budgets are hard caps: one sweep per lens (two in full-4r), max two fix rounds per review lineage.
- Review workers are read-only; only the orchestrator writes `review-ledger.md`. Fixes always flow through `plan.md` and `stage_approval`.
- `sddl-judgment-day` is opt-in, replaces 4R for its target, and confirms only what both blind judges agree on.

### project_conventions

Filled by `sddl-init` step 3 from `project-context.md`. Max 6 bullets, one line each. Omit the section entirely when nothing was established.
